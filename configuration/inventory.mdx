To run ASIMP against remote hosts you need an Ansible inventory file that lists your target systems. ASIMP reads this file when you run `play.yml`, discovers each host's OS family, and applies the appropriate hardening roles automatically.

---

## Basic Inventory Format

Ansible inventory files use a simple INI format. Hosts are grouped with `[group-name]` headers; a single host can belong to multiple groups. The example below defines separate groups for web and database servers, then combines them into a single `hardened` group that you can target as one unit.

```ini hosts.ini
[webservers]
web1.corp.example ansible_host=10.0.1.15
web2.corp.example ansible_host=10.0.1.16

[dbservers]
db1.corp.example ansible_host=10.0.2.20

[hardened:children]
webservers
dbservers
```

Save this file alongside your `play.yml` — for example as `hosts.ini` — and pass it to `ansible-playbook` with the `-i` flag.

---

## Host Variables

You can attach connection variables directly to individual hosts in your inventory. The most commonly used ones for ASIMP deployments are:

| Variable | Description | Example |
|---|---|---|
| `ansible_host` | The IP address or resolvable hostname Ansible should connect to. | `10.0.1.15` |
| `ansible_user` | The SSH user to log in as on the remote host. | `ubuntu` |
| `ansible_port` | The SSH port number. Defaults to `22`. | `2222` |
| `ansible_ssh_private_key_file` | Path to the SSH private key used for authentication. | `~/.ssh/id_rsa` |
| `ansible_become` | Whether Ansible should escalate privileges with `sudo`. | `true` |

An inventory entry with several host variables looks like this:

```ini hosts.ini
[webservers]
web1.corp.example ansible_host=10.0.1.15 ansible_user=ubuntu ansible_ssh_private_key_file=~/.ssh/id_rsa ansible_become=true
web2.corp.example ansible_host=10.0.1.16 ansible_user=ubuntu ansible_ssh_private_key_file=~/.ssh/id_rsa ansible_become=true
```

## OS Family Support

ASIMP auto-detects the Linux distribution on each host at the start of every run using the `group_by` module. It then limits hardening tasks to hosts in one of the following supported OS families:

| Distribution | OS Family |
|---|---|
| Ubuntu | `os_Ubuntu` |
| Debian | `os_Debian` |
| CentOS | `os_CentOS` |
| Red Hat Enterprise Linux | `os_RedHat` |
| Rocky Linux | `os_Rocky` |
| AlmaLinux | `os_AlmaLinux` |

Any host that does not fall into one of the supported OS families is silently skipped — ASIMP will not attempt to apply hardening roles to it. This makes it safe to include mixed-OS inventories without risk of running unsupported tasks on unrecognised systems.

## Running Against an Inventory

Pass your inventory file to `ansible-playbook` with the `-i` flag and include privilege escalation flags:

```bash
ansible-playbook -i hosts.ini -b -K play.yml
```

| Flag | Meaning |
|---|---|
| `-i hosts.ini` | Use `hosts.ini` as the inventory source. |
| `-b` | Run tasks with `become` (sudo) to gain root privileges. |
| `-K` | Prompt interactively for the sudo password before the run starts. |

---

## SSH Key Authentication

For automated or scheduled runs, use an SSH private key instead of an interactive password prompt:

```bash
ansible-playbook -i hosts.ini -b --private-key ~/.ssh/id_rsa play.yml
```

You can also set the key path per host in the inventory (see `ansible_ssh_private_key_file` in the table above), which is useful when different servers require different keys.

---

<Tip>
  Test connectivity to all inventory hosts before running a full ASIMP hardening pass:

  ```bash
  ansible all -i hosts.ini -m ping
  ```

  Every reachable host should respond with `pong`. Investigate any failures before proceeding — a host that is unreachable mid-run may leave hardening in a partial state.
</Tip>

<Warning>
  ASIMP requires `become` (sudo) privileges to install packages, modify system configuration files, and manage services. Ensure that the SSH user specified in your inventory has passwordless sudo access, or use `-K` to supply the sudo password at runtime. Runs without sufficient privileges will fail during the hardening phase.
</Warning>
