ASIMP ships with a pre-configured `ansible.cfg` that sets sensible defaults for security auditing runs. The file lives at the root of the ASIMP repository and is picked up automatically whenever you run `ansible-playbook` from that directory. This page explains each setting and when you might want to change it.

---

## Full `ansible.cfg`

```ini ansible.cfg
[defaults]

# uncomment this to disable SSH key host checking
host_key_checking = False

# use pass for vault
###vault_password_file = ./.pass

# don't create .retry files on failure
retry_files_enabled = False

# include things from galaxyproject/ansible-common-roles
roles_path = roles:common_roles:playbooks/roles
filter_plugins = common_roles/filter_plugins
lookup_plugins = common_roles/lookup_plugins

# use openssh so that we can persist connections
transport = ssh

# Don't gather host facts at the start of each play if they've already been gathered
gathering = smart

# Standardize output callback for high-fidelity human audit of deployment/auditing steps
callback_result_format = yaml
bin_ansible_callbacks = True

[ssh_connection]

# enable pipelining with OpenSSH
pipelining = True

[local]
localhost ansible_connection=local
```

---

## Settings Reference

### `host_key_checking = False`

Disables SSH host key verification. Ansible will connect to a host even if its key is not in `~/.ssh/known_hosts`. This removes the interactive prompt on first connection and is convenient when you are bringing up new servers frequently.

**In production environments, set this to `True`** so that Ansible verifies each host's key before connecting. Without host key checking, a compromised DNS entry or ARP spoofing attack could silently redirect a hardening run to a different machine (MITM).

---

### `retry_files_enabled = False`

When a playbook run fails, Ansible normally writes a `.retry` file listing the hosts that failed so you can re-target them with `-l @play.retry`. ASIMP disables this to prevent `.retry` files from accumulating in your working directory between runs. If you want retry file support, set this to `True`.

---

### `roles_path = roles:common_roles:playbooks/roles`

A colon-separated list of directories Ansible searches when resolving role names. ASIMP searches in this order:

1. `roles/` — ASIMP's own built-in roles (e.g. `update-ubuntu-ASIMP`, `reporting-ASIMP`).
2. `common_roles/` — shared roles from [galaxyproject/ansible-common-roles](https://github.com/galaxyproject/ansible-common-roles).
3. `playbooks/roles/` — additional roles bundled with specific playbooks.

If you install external roles from Ansible Galaxy into a different directory, add it to this list.

---

### `transport = ssh`

Forces Ansible to use the system's OpenSSH binary (`/usr/bin/ssh`) rather than Ansible's bundled Paramiko SSH library. OpenSSH supports SSH multiplexing and ControlMaster, which allows multiple Ansible tasks to reuse a single TCP connection to the same host — important for performance during long hardening runs.

---

### `gathering = smart`

Ansible normally gathers host facts (OS version, IP addresses, disk layout, etc.) at the start of every play. With `smart` gathering, facts are only collected once per host per playbook run. If a second play targets the same host, Ansible reuses the cached facts instead of running `setup` again. This reduces run time noticeably in multi-play playbooks like ASIMP's.

---

### `callback_result_format = yaml`

Changes the format of task results printed to the terminal from Ansible's default compact style to YAML. YAML output is easier to read when reviewing security audit results and makes copy-pasting task output into reports straightforward. `bin_ansible_callbacks = True` ensures this callback is active even for non-default callback plugins.

---

### `pipelining = True` (under `[ssh_connection]`)

Enables SSH pipelining, which allows Ansible to send multiple task payloads over the same SSH connection without opening a new channel for each one. This significantly reduces the number of SSH round-trips during a run and improves performance — particularly on high-latency links.

<Note>
  Pipelining requires that `requiretty` is **not** set in the target host's `/etc/sudoers`. Most modern Linux distributions do not set `requiretty` by default, but some hardened base images do. If you see `sudo: sorry, you must have a tty to run sudo` errors, either disable pipelining or remove `requiretty` from `sudoers`.
</Note>

---

### `[local]` Section

```ini
[local]
localhost ansible_connection=local
```

Declares that when Ansible targets `localhost`, it should use a local process connection rather than opening an SSH connection back to the same machine. This is used by `play-localhost.yml` when running ASIMP against the control node itself.

## Vault Configuration

The `ansible.cfg` includes a commented-out vault option:

```ini ansible.cfg
###vault_password_file = ./.pass
```

Ansible Vault lets you encrypt sensitive variables — such as passwords or API keys — stored in your inventory or variable files. To use vault:

**1. Encrypt a sensitive value:**

```bash
ansible-vault encrypt_string 'mypassword' --name 'ansible_password'
```

This prints an encrypted block you can paste directly into your inventory or `group_vars` files.

**2. Store the vault password in a file:**

```bash
echo 'your-vault-password' > .pass
chmod 600 .pass
```

**3. Enable automatic vault decryption by uncommenting the option in `ansible.cfg`:**

```ini ansible.cfg
vault_password_file = ./.pass
```

With this in place, `ansible-playbook` decrypts vault-protected variables automatically without prompting. If you prefer to be prompted at runtime instead, omit `vault_password_file` and pass `--ask-vault-pass` on the command line.

<Warning>
  Never commit `.pass` or any plain-text vault password file to version control. Add it to `.gitignore` immediately after creating it.
</Warning>

---

<Tip>
  For production deployments, set `host_key_checking = True` in `ansible.cfg` and use SSH key authentication rather than passwords. Combine this with a dedicated service account that has passwordless sudo access limited to the specific commands ASIMP needs, and store the private key path in your inventory using `ansible_ssh_private_key_file`.
</Tip>
