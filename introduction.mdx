ASIMP (Ansible System Integrity Management Platform) is an open-source, Ansible-powered framework for automated Linux security hardening, compliance auditing, and system integrity monitoring. It is designed for system administrators, security engineers, and DevOps teams who manage Linux fleets and need a repeatable, evidence-based process for bringing hosts into compliance with industry security benchmarks — without sacrificing visibility or control over what changes are made.

## What ASIMP Does

ASIMP organises every hardening run into three clearly defined phases, collectively known as the **Measure → Harden → Re-Measure** paradigm:

**Phase 1 — Measure (Baseline Auditing)**
Before touching anything, ASIMP runs a full dual-engine audit using OpenSCAP and Lynis. The results are saved as your baseline. You can see exactly where your system stands right now — including specific failing controls and the numeric scores — so that every subsequent improvement is quantifiable.

**Phase 2 — Harden**
ASIMP applies a layered set of hardening policies: OS-level security baselines, SSH server and client lockdown, NTP time synchronisation, kernel parameter tuning, and package integrity verification. Each action is controlled by Ansible roles, meaning the process is idempotent and auditable. Where destructive remediations are involved, ASIMP generates scripts for administrator review rather than applying them automatically.

**Phase 3 — Re-Measure (Verification & Reporting)**
After hardening, ASIMP re-runs the same OpenSCAP and Lynis audits and computes a side-by-side comparison against your baseline. The result is a concise scorecard printed to the console plus a set of detailed HTML reports saved to disk.

## What You Get

After a successful ASIMP run, the following outputs are available on the target host:

- **Comparative scorecard** — printed directly to the terminal, showing Lynis Hardening Index and OpenSCAP compliance percentage before and after hardening
- **OpenSCAP HTML reports** — detailed, human-readable audit results at:
  - `/var/log/openscap-before-report.html` (pre-hardening baseline)
  - `/var/log/openscap-after-report.html` (post-hardening verification)
- **Baseline scores JSON** — machine-readable score history saved at `/var/log/asimp-baseline-scores.json`, suitable for integration with monitoring systems
- **OpenSCAP remediation shell scripts** — auto-generated CIS Level 2 remediation scripts placed in the report directory for administrator review and selective execution

## Core Components

ASIMP is composed of three custom Ansible roles bundled in the repository, plus four external roles installed from Ansible Galaxy:

**Bundled roles:**

- **`reporting-ASIMP`** — Orchestrates the full dual-engine audit cycle. Manages OpenSCAP scans, Lynis baseline collection, score parsing, and the generation of before/after comparative reports.
- **`update-ubuntu-ASIMP`** — Handles OS package updates and repository synchronisation on Ubuntu and Debian systems, followed by `debsums` integrity verification of installed packages.
- **`lynis-ansible`** — Drives localised Lynis audit automation, extracts the Hardening Index score, and applies Lynis-specific fine-grained configuration fixes.

**External Galaxy roles:**

- **`influxdata.chrony`** — Configures the Chrony NTP daemon for accurate, secure time synchronisation.
- **`dev-sec.ssh-hardening`** — Applies production-grade SSH server and client hardening policies from the Dev-Sec project.
- **`linuxmalaysia.lynis_ansible`** — Upstream Lynis Ansible integration role providing the audit engine interface.
- **`openstack/ansible-hardening`** — Applies comprehensive OS-level security baselines derived from STIG and CIS guidance, maintained by the OpenStack project.

<Note>
  ASIMP generates OpenSCAP CIS Level 2 remediation scripts for administrator review rather than blindly applying destructive fixes. This gives you full control over which remediations are executed on your systems, ensuring that no change is made without explicit sign-off from a qualified administrator.
</Note>
