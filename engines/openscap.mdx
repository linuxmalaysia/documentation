ASIMP integrates OpenSCAP — a NIST-certified compliance scanning tool — to measure your system's adherence to the CIS (Center for Internet Security) Level 2 Server benchmark. Scans run automatically in Phase 1 (before hardening) and Phase 3 (after hardening), giving you a precise, measurable picture of your security posture at every stage of the pipeline.

---

## What OpenSCAP Measures

OpenSCAP evaluates your system against a structured set of rules defined in the CIS Level 2 Server profile:

**Profile ID:** `xccdf_org.ssgproject.content_profile_cis_level2_server`

The profile covers six broad categories of security controls:

| Category | Examples |
|---|---|
| **Filesystem hardening** | Partition mount options, world-writable file restrictions |
| **User account policies** | Password aging, minimum length, account lockout |
| **Service configuration** | Disabling unnecessary services, securing enabled ones |
| **Network settings** | TCP/IP stack hardening, firewall rule verification |
| **Audit logging** | `auditd` configuration, log retention policies |
| **Access controls** | sudo rules, PAM configuration, file permission baselines |

The result of each scan is a **compliance score expressed as a percentage (0–100%)**. ASIMP uses the following thresholds:

| Threshold | Score |
|---|---|
| ✅ Target | 90% or above |
| ⚠️ Minimum acceptable | 75% |
| ❌ Non-compliant | Below 75% |

## How ASIMP Runs OpenSCAP

The scanning command and datastream source differ by operating system. ASIMP detects your OS and selects the correct path automatically.

<Tabs>
  <Tab title="Ubuntu">
    On Ubuntu, ASIMP fetches the **latest SCAP Security Guide (SSG)** release directly from the official [ComplianceAsCode/content](https://github.com/ComplianceAsCode/content) repository on GitHub. This ensures your scan always uses the most up-to-date rule definitions for your Ubuntu version.

    **What ASIMP does:**
    1. Queries the GitHub Releases API for the latest `scap-security-guide-*.zip`
    2. Downloads and extracts the zip
    3. Locates the version-specific datastream: `ssg-ubuntu<version>-ds.xml` (e.g., `ssg-ubuntu2404-ds.xml`)
    4. Runs the evaluation

    ```bash
    oscap xccdf eval \
      --profile xccdf_org.ssgproject.content_profile_cis_level2_server \
      --results /var/log/openscap-before-results.xml \
      --report /var/log/openscap-before-report.html \
      ssg-ubuntu2404-ds.xml
    ```

    The same command structure is used for the post-hardening scan, writing results to `openscap-after-results.xml` and `openscap-after-report.html`.
  </Tab>
  <Tab title="RHEL / CentOS / Rocky Linux">
    On RHEL-family systems, ASIMP uses the **pre-installed SCAP Security Guide datastreams** shipped with the `scap-security-guide` package. No download is required.

    **Datastream locations:**

    | Distribution | Datastream path |
    |---|---|
    | RHEL | `/usr/share/xml/scap/ssg/content/ssg-rhel<version>-ds.xml` |
    | CentOS | `/usr/share/xml/scap/ssg/content/ssg-centos<version>-ds.xml` |
    | Rocky Linux | `/usr/share/xml/scap/ssg/content/ssg-rocky<version>-ds.xml` |

    ```bash
    oscap xccdf eval \
      --profile xccdf_org.ssgproject.content_profile_cis_level2_server \
      --results /var/log/openscap-before-results.xml \
      --report /var/log/openscap-before-report.html \
      /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml
    ```

    ASIMP automatically resolves the correct datastream for your major OS version at runtime.
  </Tab>
</Tabs>

## USN OVAL Vulnerability Assessment

<Info>
  This assessment runs on **Ubuntu only** and is performed in addition to the CIS profile scan.
</Info>

Ubuntu Security Notices (USNs) are official security advisories from Canonical. To check whether your system has unpatched vulnerabilities tracked by USNs, ASIMP performs a separate OVAL evaluation:

1. **Downloads** Canonical's official OVAL definition file from `security-metadata.canonical.com`
2. **Decompresses** the `.bz2` archive
3. **Runs** the OVAL evaluation:

```bash
oscap oval eval \
  --report /var/log/oval-noble.html \
  com.ubuntu.noble.usn.oval.xml
```

The OVAL results are stored alongside your CIS scan outputs and can be reviewed in the generated HTML report for your Ubuntu release codename (e.g., `oval-noble.html` for Ubuntu 24.04).

## Understanding Your OpenSCAP Report

After each scan phase, ASIMP writes two report files per run:

| File | Purpose |
|---|---|
| `/var/log/openscap-before-report.html` | Human-readable compliance report (before hardening) |
| `/var/log/openscap-before-results.xml` | Machine-readable XCCDF results (before hardening) |
| `/var/log/openscap-after-report.html` | Human-readable compliance report (after hardening) |
| `/var/log/openscap-after-results.xml` | Machine-readable XCCDF results (after hardening) |

**Opening the HTML report:**

Open the file in any web browser. You do not need any special tools — it is a self-contained HTML document.

```bash
# Copy to your workstation, then open in a browser
scp user@target:/var/log/openscap-before-report.html ~/Downloads/
```

**What the report contains:**

- **Summary score** — your overall percentage compliance at the top of the report
- **Rule-by-rule results** — every evaluated rule listed as `pass`, `fail`, or `notapplicable`
- **Severity classification** — each rule tagged `high`, `medium`, or `low` by CIS
- **Rule description** — what each rule checks and why it matters
- **Fix guidance** — the specific remediation steps for each failing rule

**Comparing before vs. after:**

Open both `openscap-before-report.html` and `openscap-after-report.html` side-by-side in your browser to see exactly which rules moved from `fail` to `pass` as a result of ASIMP's hardening phase. The score difference between the two reports represents your measurable security improvement.

## Remediation Scripts

Alongside the scan reports, ASIMP generates a tailored bash remediation script for your system using `oscap xccdf generate fix`:

**Script location:** `/var/log/remediate-<release>-latest.sh`

For example, on Ubuntu 24.04 Noble: `/var/log/remediate-noble-latest.sh`

This script contains the exact shell commands required to bring every failing rule into compliance with the CIS Level 2 Server profile on your specific OS version and configuration.

<Warning>
  **Do NOT run this script automatically or without careful review.**

  The remediation script is generated for your inspection and controlled use only. It is never auto-applied by ASIMP. Certain remediations — including bootloader parameter changes, aggressive PAM configuration, and SSH policy modifications — **can break system boot, lock out remote access, or disrupt running services** if applied without understanding their impact on your environment.

  Review every section before executing any part of the script.
</Warning>

**How to review and selectively apply remediations:**

```bash
# Page through the full script
less /var/log/remediate-noble-latest.sh

# Inspect a specific section (e.g., searching for SSH rules)
grep -A 20 "SSH" /var/log/remediate-noble-latest.sh

# Execute only a specific section you have reviewed and understand
bash -x /var/log/remediate-noble-latest.sh 2>&1 | tee /var/log/remediate-run.log
```

Each section of the script is annotated with the corresponding XCCDF rule ID so you can cross-reference it against the HTML report before applying it.

## Graceful Fallback

ASIMP is designed to fail safely when OpenSCAP scanning is not possible on a given host.

If any of the following conditions are detected:

- The `openscap-scanner` package cannot be installed
- No compatible datastream XML file is found for the target OS
- The CIS Level 2 Server profile is not present in the located datastream

ASIMP sets the internal flag `openscap_scan_supported: false` and **skips the scan entirely** rather than failing the playbook. The rest of the hardening pipeline continues normally, and the missing scan is clearly flagged in the final scorecard so you know the result is absent rather than silently incorrect.
