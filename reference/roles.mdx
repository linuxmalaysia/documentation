ASIMP's functionality is divided across three local roles and four Ansible Galaxy roles. Each role handles a specific layer of the hardening pipeline — from auditing and package updates through to SSH hardening and NTP synchronisation.

---

## Local Roles

### reporting-ASIMP

Manages baseline generation and comparative reporting. This role is the bookend of the ASIMP pipeline — it runs **twice**: once before hardening to capture the pre-change state, and once after to measure what improved.

**What it does:**
- Runs an **OpenSCAP** scan against the CIS Security Linux Level 2 profile
- Runs a **Lynis** audit for compliance profiling
- In the `before` phase: writes results to `/var/log/asimp-baseline-scores.json`
- In the `after` phase: reads the baseline file, runs a second audit, and outputs a **comparative scorecard** to the terminal
- Generates an **HTML report** summarising findings

**Key variable:**

| Variable | Values | Description |
|---|---|---|
| `reporting_phase` | `before` \| `after` | Controls which half of the reporting pipeline runs |

<Note>
  If OpenSCAP datastreams are not found on the target system, `reporting-ASIMP` sets `openscap_scan_supported: false` and falls back gracefully — the Lynis audit still runs. See [Troubleshooting](/reference/troubleshooting) for how to install the required packages.
</Note>

---

### update-ubuntu-ASIMP

Handles OS package updates and integrity checks on Ubuntu/Debian hosts (and RHEL/CentOS via the equivalent update-rhel tasks). Runs asynchronously for large update sets to avoid SSH timeout issues.

**What it does:**
- Applies OS package updates (upgrade, dist-upgrade, or safe-upgrade depending on configuration)
- Runs **debsums** to verify installed package files against their checksums
- Reports any CHANGED or MISSING files from debsums output

**Variables:**

| Variable | Type | Description |
|---|---|---|
| `upgrade_ubuntu_check` | `yes` \| `no` | Run `apt-get upgrade` |
| `dist_upgrade_ubuntu_check` | `yes` \| `no` | Run `apt-get dist-upgrade` |
| `safe_upgrade_ubuntu_check` | `yes` \| `no` | Run `apt-get --with-new-pkgs upgrade` (safer upgrade path) |
| `debsums_ubuntu_check` | `yes` \| `no` | Run debsums package integrity verification |

<Warning>
  `dist_upgrade_ubuntu_check` may remove packages to resolve dependency conflicts. Review what will be removed before enabling on production systems.
</Warning>

---

### lynis-ansible

Manages Lynis installation and audit execution. Lynis is an open-source security auditing tool — this role ensures it is installed, up to date, and run against the system.

**What it does:**
- Installs Lynis via the system package manager (if `lynis_use_packages: yes`)
- Runs a full system audit: `lynis audit system`
- Produces a Lynis report used by `reporting-ASIMP` for scoring

**Variables:**

| Variable | Type | Description |
|---|---|---|
| `lynis_use_packages` | `yes` \| `no` | Install Lynis from the OS package manager rather than from source |
| `lynis_audit_system_linux` | `yes` \| `no` | Execute `lynis audit system` during the role run |

## Galaxy Roles

These roles are pulled from Ansible Galaxy or GitHub at install time via `requirements.yml`. Run `ansible-galaxy install -r requirements.yml` before your first playbook execution.

| Role | Version | Source | Purpose |
|---|---|---|---|
| `influxdata.chrony` | `1.3.0` | Ansible Galaxy | NTP time synchronisation with configurable server list |
| `dev-sec.ssh-hardening` | `9.7.0` | Ansible Galaxy | Hardened SSH server and client configuration |
| `linuxmalaysia.lynis_ansible` | `master` | Ansible Galaxy | Lynis package management and system hardening tasks |
| `openstack/ansible-hardening` | `master` | GitHub | Comprehensive OS security baselines: kernel parameters, PAM, resource limits |

<Note>
  `openstack/ansible-hardening` is sourced directly from GitHub rather than Galaxy. Ensure you have internet access (or a mirrored copy) when running `ansible-galaxy install -r requirements.yml`.
</Note>

## Role Execution Order

The following order reflects how roles run inside `play.yml` and `play-localhost.yml`:

1. `reporting-ASIMP` (`reporting_phase: before`) — pre-hardening baseline
2. _(Pre-flight safety checks — not a role, built-in tasks)_
3. `update-ubuntu-ASIMP` / update-rhel — OS package updates and debsums
4. `openstack/ansible-hardening` — kernel, PAM, and OS-level security baselines
5. `dev-sec.ssh-hardening` — SSH server and client hardening
6. `influxdata.chrony` — NTP synchronisation
7. `lynis-ansible` — Lynis installation and audit execution
8. `reporting-ASIMP` (`reporting_phase: after`) — post-hardening audit and scorecard

## Overriding Role Variables

**In a playbook `vars` block:**

```yaml
- hosts: all
  become: true
  vars:
    reporting_phase: before
    debsums_ubuntu_check: no
    lynis_use_packages: yes
  roles:
    - reporting-ASIMP
    - update-ubuntu-ASIMP
    - lynis-ansible
```

**Per-host in your inventory (`hosts.ini`):**

```ini
[os_Ubuntu]
web01 ansible_host=192.168.1.10 debsums_ubuntu_check=no
web02 ansible_host=192.168.1.11 dist_upgrade_ubuntu_check=yes
```

**Per-group in `group_vars/`:**

```yaml
# group_vars/os_Ubuntu.yml
upgrade_ubuntu_check: yes
safe_upgrade_ubuntu_check: no
debsums_ubuntu_check: yes
lynis_use_packages: yes
```
