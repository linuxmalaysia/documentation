---
title: "Get Started with ASIMP in Under 10 Minutes"
sidebarTitle: "Quick Start"
description: "Install ASIMP, set up your Python environment, and run your first security hardening and compliance audit on a Linux host."
---

By the end of this guide you will have run ASIMP against a Linux host, observed the three-phase Measure → Harden → Re-Measure pipeline execute in real time, and reviewed a before/after compliance scorecard showing the measurable security improvement achieved.

<Warning>
  ASIMP applies real system changes including SSH configuration updates, kernel parameter tuning, and OS hardening policies. Always run in a test environment first, or take a snapshot or backup before hardening production systems.
</Warning>

<Tip>
  First time? Start with `play-localhost.yml` to harden your own machine before targeting remote hosts. It requires no inventory file and gives you immediate, hands-on familiarity with the full pipeline.
</Tip>

<Steps>
  <Step title="Check Prerequisites">
    Confirm that Python 3.8+ and Ansible 9.0+ are available on your control node, and that you have a supported Linux target host (Ubuntu, Debian, RHEL, CentOS, or Rocky Linux) with SSH access and `sudo` privileges.

    ```bash
    python3 --version && ansible --version
    ```

    You should see Python 3.8 or later and Ansible core 2.16 or later (packaged as Ansible 9.x). If Ansible is not yet installed, it will be installed in the next step via `pip`.
  </Step>

  <Step title="Set Up Python Virtual Environment">
    Create an isolated Python virtual environment and install ASIMP's Python dependencies. Using a virtual environment prevents version conflicts with any system-wide Python packages.

    ```bash
    python3 -m venv /tmp/venv
    source /tmp/venv/bin/activate
    pip install -r requirements.txt
    ```

    `requirements.txt` installs the following packages:

    | Package | Purpose |
    |---|---|
    | `ansible>=9.0.0` | Ansible automation engine |
    | `ansible-lint` | Playbook linting and best-practice checks |
    | `jmespath` | JSON query support for Ansible filters |
    | `cryptography` | Cryptographic primitives for Ansible Vault and SSH key handling |
  </Step>

  <Step title="Install Ansible Galaxy Roles">
    Download the four external Ansible roles that ASIMP depends on for NTP synchronisation, SSH hardening, OS hardening, and Lynis auditing:

    ```bash
    ansible-galaxy install -r requirements.yml
    ```

    This installs the following roles to `~/.ansible/roles` (or a custom path configured in `ansible.cfg`):

    | Role | Version |
    |---|---|
    | `influxdata.chrony` | 1.3.0 |
    | `dev-sec.ssh-hardening` | 9.7.0 |
    | `linuxmalaysia.lynis_ansible` | master |
    | `openstack/ansible-hardening` | master |
  </Step>

  <Step title="Run ASIMP on Localhost">
    Activate your virtual environment (if not already active) and execute the localhost hardening playbook:

    ```bash
    source /tmp/venv/bin/activate
    ansible-playbook --connection=local -b -K play-localhost.yml
    ```

    **Flag reference:**

    | Flag | Meaning |
    |---|---|
    | `--connection=local` | Connect to `localhost` directly instead of over SSH |
    | `-b` | Enable `become` (privilege escalation to root / sudo) |
    | `-K` | Prompt for the become password before execution begins |

    ASIMP will run Phase 1 (baseline audit), Phase 2 (hardening), and Phase 3 (re-audit and reporting) in sequence. The full run typically takes 10–30 minutes depending on the host and the number of packages to update.
  </Step>

  <Step title="Review Your Results">
    When the playbook completes, ASIMP prints a consolidated security scorecard to the terminal:

    ```text
    ========================================================================
                     ASIMP SECURITY HARDENING REPORT
    ========================================================================
    Tool       | Baseline (Min) | Before Hardening | After Hardening | Target
    ------------------------------------------------------------------------
    Lynis HI   | 75             | 62               | 88               | 85+
    OpenSCAP % | 75.0%          | 58.4%            | 91.2%            | 90%+
    ========================================================================
    Reports generated successfully:
      - OpenSCAP Before Report: /var/log/openscap-before-report.html
      - OpenSCAP After Report:  /var/log/openscap-after-report.html
    ========================================================================
    ```

    For a deep-dive into individual failing controls, open the HTML reports in a browser:

    - **Pre-hardening audit:** `/var/log/openscap-before-report.html`
    - **Post-hardening audit:** `/var/log/openscap-after-report.html`

    Machine-readable scores are also saved at `/var/log/asimp-baseline-scores.json` for integration with dashboards or monitoring pipelines.
  </Step>
</Steps>
