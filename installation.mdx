ASIMP runs as an Ansible playbook collection — there is no compiled binary to install. Before your first run you need Python 3, a virtual environment, and the required Ansible Galaxy roles installed and accessible on your Ansible control node. This page walks you through each step.

## System Requirements

Ensure your control node meets the following requirements before proceeding:

- **Python 3.8 or later** — required to run Ansible and its dependencies
- **Ansible Core 9.0.0 or later** — installed via `pip` as part of the Python dependencies
- **SSH access to target hosts** — or use `--connection=local` for localhost mode
- **`sudo` / `become` privileges on target hosts** — required for all hardening tasks
- **Minimum 512 MB free disk space on `/`** — ASIMP performs a pre-flight check and will abort if this threshold is not met, preventing mid-upgrade disk exhaustion and package corruption

## Install Python Dependencies

Clone or download the ASIMP repository, then create an isolated Python virtual environment and install all required packages from `requirements.txt`:

<CodeGroup>
  ```bash Create virtual environment
  python3 -m venv /tmp/venv
  source /tmp/venv/bin/activate
  pip install -r requirements.txt
  ```
</CodeGroup>

`requirements.txt` pins the following packages:

| Package | Purpose |
|---|---|
| `ansible>=9.0.0` | Ansible automation engine and `ansible-playbook` CLI |
| `ansible-lint` | Static analysis and best-practice linting for playbooks |
| `jmespath` | JSON query language support used by Ansible's `json_query` filter |
| `cryptography` | Cryptographic primitives for Ansible Vault and SSH key operations |

Using a virtual environment is strongly recommended. It isolates ASIMP's dependencies from any system-wide Python packages and avoids version conflicts.

## Install Ansible Galaxy Roles

With your virtual environment active, install the four external Ansible roles defined in `requirements.yml`:

```bash
ansible-galaxy install -r requirements.yml
```

The following roles will be downloaded and installed:

| Role | Version | Purpose |
|---|---|---|
| `influxdata.chrony` | 1.3.0 | NTP time synchronisation — configures the Chrony daemon for accurate, secure system time |
| `dev-sec.ssh-hardening` | 9.7.0 | Applies production-grade SSH server and client hardening policies from the Dev-Sec project |
| `linuxmalaysia.lynis_ansible` | master | Lynis audit and hardening automation — drives the Lynis engine and extracts the Hardening Index score |
| `openstack/ansible-hardening` | master | Comprehensive OS-level security baselines derived from STIG and CIS guidance, maintained by OpenStack |

<Note>
  Galaxy roles are installed to `~/.ansible/roles` by default. ASIMP also searches the `roles/` and `common_roles/` directories within the project directory. These additional search paths are configured in `ansible.cfg` so that all bundled roles are discovered automatically alongside the installed Galaxy roles.
</Note>

## Verify Installation

Confirm that Ansible is available and that all Galaxy roles were installed successfully:

```bash
ansible --version
ansible-galaxy list
```

`ansible --version` should report Ansible core 2.16.x or later (the core version that ships with the Ansible 9.x package). `ansible-galaxy list` should include all four roles listed in the table above. If any role is missing, re-run `ansible-galaxy install -r requirements.yml`.
